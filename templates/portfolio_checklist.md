# Portfolio checklist

Print this page or copy it into each project's notes.

## Before publishing one project
- [ ] The first paragraph of the README states the finding with a number
- [ ] The main chart's title states the finding
- [ ] The data source, link, period, download date and licence are recorded
- [ ] Cleaning decisions are listed, with counts
- [ ] Two or three limitations that could change the conclusion are stated
- [ ] The code runs from top to bottom on a fresh download
- [ ] Raw data that can't be shared is downloaded by a script, not committed
- [ ] No API keys, passwords or personal data are in the repository
- [ ] Spelling and grammar have been checked
- [ ] There is a one-line CV summary with the finding in it

## Reviewing the whole portfolio
- [ ] Three or four finished projects, best one first
- [ ] Between them they cover the skills in the job ads you're targeting
- [ ] At least one uses SQL, at least one shows deeper analysis, at least one is something a person could use (a dashboard or report)
- [ ] At least one uses data from the industry or country you want to work in
- [ ] None is a straight copy of a tutorial or a famous notebook
- [ ] Each repository has a clear name and a one-line description
- [ ] Your GitHub profile has a short README pointing to the best projects
- [ ] You can talk for five minutes about each project: the question, a surprise, a decision you'd change, and what you'd do next
